# 星かぞえ (hoshi-kazoe)

夜空の写真に写った星を数えて、空の暗さ(ボートルスケール)を幅つきで推定するWebアプリ。「ここは都会の空か」を星の数で言います。

## なぜ写真を読み込む方式なのか

ブラウザがカメラから受け取れるのは動画です。1コマの露光は長くても 1/10 秒前後で、`exposureTime` を変えられるのは Android の Chrome の一部だけ、iOS の Safari には手段がありません。6 等星を写すには数秒の露光がいるので、コマを重ねても(ノイズが減るだけで)暗い星は写りません。

そこで主な入力は、スマホのカメラアプリの夜景・天体モードで撮った写真にしました。カメラで動画のコマを 60 枚重ねるモードも「実験」として残してありますが、そこで出る結果は「少なくともこのくらい暗い」という下限扱いです。

## しくみ

1. 輝度にして 32px タイルごとに背景(中央値)とノイズ(MAD)を測り、背景を引いて 3×3 でならす
2. ノイズの 5 倍を超える極大を種に 2.5 倍まで領域を広げる。重なった星は極大の数で分ける。長い線(飛行機・衛星)と白飛びした大きな塊(月・街灯)は除く
3. 画面の上 30% を空の基準にして、手前のシルエット・ざらついた輪郭・月の周りのタイルは数えない
4. 35mm 換算焦点距離(EXIF、なければ 26mm と仮定して表示)から写った空の立体角を出し、全天に換算
5. 全天の累積星数表(1 等で約 3 倍)から写真の限界等級 → 「夜景モードは肉眼より 0.5 等深い」と仮定して肉眼の限界等級(NELM) → ボートル / SQM
6. 誤差 = 数のポアソン誤差 + カメラの深さの違い ±0.7 等 + 天の川の近くかどうか ±0.35 等。結果はクラスの範囲で示す

星が 3 個未満、または空として使える部分が 1 割未満なら「測れません」と出します。

## 開発

    pnpm install
    pnpm dev    # http://localhost:5890
    pnpm test

計算は `src/lib/` の純粋関数(Vitest)、画面は `src/app.js` と `src/ui/`。`src/lib/synth.js` で「ボートル n の空を撮った写真」を合成でき、テストとデモはこれで往復を確かめています。`window.__app` から `analyze` / `makeSky` / `runDemo` / `loadFile` を呼べます。

写真はブラウザの中だけで解析し、どこにも送りません。
